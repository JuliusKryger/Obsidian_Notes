### Reading Paper:

#### **What is SQL Injection?**

SQL Injection is a code injection technique that exploits vulnerabilities in an application’s interaction with its database. Attackers manipulate SQL queries to execute malicious commands, gain unauthorized access, or compromise data integrity.

---

### When is a Program Vulnerable to SQL Injection?

1. **Dynamic SQL Queries:**
    
    - Programs that build SQL queries using string concatenation or user input.
        
    - Example:
        
        ```
        string query = "SELECT * FROM USERS WHERE USERNAME = '" + userInput + "'";
        ```
        
2. **Lack of Input Validation:**
    
    - Applications that do not sanitize or validate user input are at risk.
        
3. **Direct Execution of User Input:**
    
    - Directly embedding user input into database queries without filtering.
        
4. **Error Messages Revealing Sensitive Information:**
    
    - Detailed error messages provide attackers clues about the database schema.
        

---

### An Example of Malicious SQL Injection:

#### **Scenario:**

- A login form accepting `USERNAME` and `PASSWORD` inputs.
    
- Query:
    
    ```
    SELECT * FROM USERS WHERE USERNAME = 'admin' AND PASSWORD = '1234';
    ```
    

#### **Injection:**

- User enters:
    
    - `USERNAME`: `admin' --`
        
    - `PASSWORD`: `anything`
        
- Query becomes:
    
    ```
    SELECT * FROM USERS WHERE USERNAME = 'admin' --' AND PASSWORD = 'anything';
    ```
    
- Effect: Logs in as `admin` without validating the password.

### Protection Against SQL Injection Using Stored Functions:

1. **Parameterized Queries (Prepared Statements):**
    
    - Use placeholders for input parameters to separate query logic from data.
        
    - **Example in C#:**
        
        ```
        string query = "SELECT * FROM USERS WHERE USERNAME = @username AND PASSWORD = @password;";
        SqlCommand cmd = new SqlCommand(query, connection);
        cmd.Parameters.AddWithValue("@username", userInput);
        cmd.Parameters.AddWithValue("@password", passwordInput);
        ```
        
2. **Stored Functions and Procedures:**
    
    - Encapsulate SQL logic in the database to minimize direct user input handling.
        
    - **Example:**
        
        ```
        CREATE PROCEDURE AuthenticateUser (
            @USERNAME NVARCHAR(50),
            @PASSWORD NVARCHAR(50)
        )
        AS
        BEGIN
            SELECT COUNT(*)
            FROM USERS
            WHERE USERNAME = @USERNAME AND PASSWORD = HASHBYTES('SHA2_256', @PASSWORD);
        END;
        ```
        
3. **Input Validation and Escaping:**
    
    - Validate input for expected formats and lengths.
        
    - Use escaping functions to neutralize special characters (e.g., `'`).
        
4. **Principle of Least Privilege:**
    
    - Ensure the database user has only the permissions required for specific tasks.
        

---

### Bullet Points:

- SQL Injection manipulates queries to execute unauthorized commands.
    
- **Vulnerabilities:** Dynamic queries, lack of validation, direct input execution.
    
- **Attack Example:** Altering a login query to bypass authentication.
    
- **Protection Methods:**
    
    - Use parameterized queries.
        
    - Implement stored functions and procedures.
        
    - Validate and sanitize inputs.
        
    - Follow the principle of least privilege.
