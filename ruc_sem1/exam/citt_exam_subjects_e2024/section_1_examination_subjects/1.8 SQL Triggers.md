### Reading Paper:

#### **What are SQL Triggers?**

SQL triggers are special stored programs that are automatically executed in response to specific events on a table or view. Triggers help enforce business rules, maintain data integrity, and automate database tasks.

---

### Purpose:

- **Data Validation**: Enforce rules before or after data modification.
    
- **Audit Trails**: Track changes to data for logging purposes.
    
- **Automated Updates**: Perform related updates when data changes in a table.
    
- **Integrity Maintenance**: Ensure data consistency across related tables.
    

---

### Language Constructs Specific for Triggers:

1. **Trigger Events:**
    
    - Define the actions that activate the trigger.
        
    - **Types:** `INSERT`, `UPDATE`, `DELETE`.
        
    - Example:
        
        ```
        CREATE TRIGGER before_insert_student
        BEFORE INSERT ON STUDENT
        FOR EACH ROW
        BEGIN
          -- Trigger logic
        END;
        ```
        
2. **Trigger Timing:**
    
    - Specify when the trigger is fired relative to the triggering event.
        
    - **Options:** `BEFORE` or `AFTER`.
        
    - Example:
        
        - `BEFORE INSERT`: Validate data before adding it.
            
        - `AFTER DELETE`: Log or archive deleted rows.
            
3. **Trigger Scope:**
    
    - Define whether the trigger applies to each row (`FOR EACH ROW`) or to the entire statement (`FOR EACH STATEMENT`).
        
4. **Trigger Body:**
    
    - Contains the logic executed by the trigger.
        
    - Can include SQL statements like `INSERT`, `UPDATE`, or `DELETE`.
        
5. **Referencing:**
    
    - Use `NEW` and `OLD` keywords to access values before and after the triggering event.
        
    - **Example:**
        
        ```
        CREATE TRIGGER update_audit
        AFTER UPDATE ON STUDENT
        FOR EACH ROW
        BEGIN
          INSERT INTO STUDENT_AUDIT(ROLL_NO, OLD_NAME, NEW_NAME)
          VALUES (NEW.ROLL_NO, OLD.NAME, NEW.NAME);
        END;
        ```

### Use for Integrity Maintenance and Data Update:

1. **Enforcing Business Rules:**
    
    - Example: Prevent negative values in the `SALARY` column.
        
        ```
        CREATE TRIGGER prevent_negative_salary
        BEFORE UPDATE ON EMPLOYEE
        FOR EACH ROW
        BEGIN
          IF NEW.SALARY < 0 THEN
            SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Salary cannot be negative';
          END IF;
        END;
        ```
        
2. **Maintaining Referential Integrity:**
    
    - Example: Automatically delete child records when a parent record is removed.
        
        ```
        CREATE TRIGGER delete_cascade
        AFTER DELETE ON PARENT
        FOR EACH ROW
        BEGIN
          DELETE FROM CHILD
          WHERE CHILD.PARENT_ID = OLD.PARENT_ID;
        END;
        ```
        
3. **Audit Trails:**
    
    - Example: Log every deletion from the `ORDERS` table.
        
        ```
        CREATE TRIGGER log_deletions
        AFTER DELETE ON ORDERS
        FOR EACH ROW
        BEGIN
          INSERT INTO ORDER_LOG (ORDER_ID, DELETED_AT)
          VALUES (OLD.ORDER_ID, NOW());
        END;
        ```
        

---

### Bullet Points:

- **Triggers:** Automatically executed in response to `INSERT`, `UPDATE`, or `DELETE` events.
    
- **Timing:** Specify `BEFORE` or `AFTER` the triggering event.
    
- **Scope:** Apply to rows (`FOR EACH ROW`) or statements (`FOR EACH STATEMENT`).
    
- **Referencing:** Use `NEW` and `OLD` for accessing values.
    
- **Applications:** Enforce rules, maintain integrity, track changes, and automate updates.
