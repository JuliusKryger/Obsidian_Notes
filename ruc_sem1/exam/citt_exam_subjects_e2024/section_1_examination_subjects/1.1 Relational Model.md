### Structure of Relational Databases

The structure of relational databases is foundational to understanding how data is organized and managed efficiently. Relational databases rely on a table-based format, where data is stored in relations (tables) that facilitate querying, data integrity, and scalability. Each table is uniquely named and is composed of rows (tuples) and columns (attributes), enabling a systematic and logical approach to data handling.

#### Relational Model

- Represents data in tables (relations), where each table has a unique name.
    
- **Example:** Table `STUDENT` with attributes `ROLL_NO`, `NAME`, `ADDRESS`, `PHONE`, and `AGE`.
    

#### Key Terminologies

- **Attribute**: Properties/columns defining entities (e.g., `ROLL_NO`, `NAME`).
    
- **Relation Schema**: Structure of a relation (e.g., `STUDENT(ROLL_NO, NAME, ADDRESS, PHONE, AGE)`).
    
- **Tuple**: Rows in a table (e.g., a single student's data).
    
- **Degree**: Number of attributes in a relation (e.g., `STUDENT` has 5 attributes).
    
- **Cardinality**: Number of tuples (rows) in a relation (e.g., `STUDENT` has 4 tuples).
    
- **Relation Instance**: Set of tuples at a specific time. Changes with updates.
    
- **NULL Values**: Unknown or unavailable values (e.g., `PHONE` for `ROLL_NO = 4` is `NULL`).

### Keys in Relational Databases

Keys are fundamental in relational databases as they define how data is uniquely identified and related between tables. Proper understanding and usage of keys ensure data integrity and facilitate efficient querying.

#### Types of Keys

- **Primary Key**: Uniquely identifies rows (e.g., `ROLL_NO` in `STUDENT`). A table can have only one primary key.
    
- **Candidate Key**: Attributes that can qualify as primary keys. All candidate keys are unique but only one is chosen as the primary key.
    
- **Super Key**: A set of one or more attributes that uniquely identify rows. Every primary key is a super key, but not all super keys are primary keys.
    
- **Foreign Key**: An attribute in one table linking to a primary key in another table (e.g., `ROLL_NO` in `STUDENT_SPORTS` linking to `STUDENT`). Ensures referential integrity.
    
- **Composite Key**: A combination of multiple attributes to uniquely identify rows (e.g., `(ROLL_NO, SUBJECT)` in a table tracking student grades).
    
- **Alternate Key**: Candidate keys that are not selected as the primary key but can still uniquely identify rows.
    

These keys serve distinct purposes in database design, making them essential for maintaining consistency, avoiding redundancy, and enabling relationships between data entities.

### Fundamental Operations in Relational Algebra

#### 1. Selection (σ)

- Filters rows based on a condition.
    
- **Syntax**: σ_condition(Relation)
    
- **Example**: Extract students aged over 18.
    
    **Result:**
    
    |ROLL_NO|NAME|ADDRESS|PHONE|AGE|
    |---|---|---|---|---|
    |3|SUJIT|ROHTAK|9156253131|20|
    

#### 2. Projection (π)

- Selects specific columns.
    
- **Syntax**: π_AttributeList(Relation)
    
- **Example**: Extract `ROLL_NO` and `NAME`.
    
    **Result:**
    
    |   |   |
    |---|---|
    |ROLL_NO|NAME|
    |1|RAM|
    |2|RAMESH|
    |3|SUJIT|
    |4|SURESH|
    

#### 3. Cross Product (×)

- Combines two relations. For every tuple in one relation, combines with all tuples in another.
    
- **Syntax**: Relation1 × Relation2
    
- **Example**: Combine `STUDENT` and `STUDENT_SPORTS`.
    
    **Result:** Total tuples = Rows(Relation1) × Rows(Relation2).
    

#### 4. Union (∪)

- Combines tuples from two relations. Removes duplicates.
    
- **Syntax**: Relation1 ∪ Relation2
    
- **Example**: Find all persons who are either students or employees.
    

#### 5. Set Difference (−)

- Returns tuples in one relation but not in another.
    
- **Syntax**: Relation1 − Relation2
    
- **Example**: Find students who are not employees.
    

#### 6. Rename (ρ)

- Renames relations or attributes.
    
- **Syntax**: ρ_NewName(AttributeList)(Relation)
    
- **Example**: Rename `STUDENT` to `STUDENT1`.
