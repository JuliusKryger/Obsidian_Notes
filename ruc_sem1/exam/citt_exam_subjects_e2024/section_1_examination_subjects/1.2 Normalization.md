### Reading Paper:

#### **What is Normalization?**

Normalization is the process of organizing data in a database to reduce redundancy and improve data integrity. It involves dividing large tables into smaller, related tables and defining relationships between them. This ensures that the database structure is efficient and can handle updates, deletions, and insertions without introducing anomalies.

#### **Goals of Normalization:**

1. **Eliminate Redundancy:** Avoid storing the same data multiple times.
    
2. **Ensure Data Integrity:** Maintain accuracy and consistency of data.
    
3. **Simplify Maintenance:** Reduce complexity in updating and managing the database.
    
4. **Minimize Anomalies:** Prevent insertion, deletion, and update anomalies.
    

#### **Key Concepts in Normalization:**

- **Functional Dependency:**
    
    - A functional dependency exists when one attribute uniquely determines another attribute. For example, in a relation `STUDENT(ROLL_NO, NAME)`, `ROLL_NO -> NAME` indicates that the ROLL_NO uniquely determines the NAME.
        
- **Superkey:**
    
    - A superkey is a set of attributes that uniquely identifies a tuple in a relation. It may contain additional attributes that are not necessary for unique identification.
        
- **Candidate Key:**
    
    - A candidate key is a minimal superkey. It uniquely identifies a tuple, but it contains no unnecessary attributes. For example, in the `STUDENT` relation, `ROLL_NO` is a candidate key.
        

#### **Boyce-Codd Normal Form (BCNF):**

BCNF is a stricter version of the Third Normal Form (3NF). A relation is in BCNF if, for every non-trivial functional dependency `X -> Y`, `X` is a superkey. This ensures there are no redundancy-causing dependencies.

##### **Steps to Achieve BCNF:**

1. Identify functional dependencies in the relation.
    
2. Check if each functional dependency satisfies the BCNF condition.
    
3. If not, decompose the relation into smaller relations that meet the BCNF requirements while preserving dependencies.
    

##### **Example:**

Given a relation `COURSE(COURSE_ID, STUDENT_ID, INSTRUCTOR)`, assume:

- Functional Dependencies:
    
    - `COURSE_ID -> INSTRUCTOR`
        
    - `STUDENT_ID -> COURSE_ID`
        

To normalize:

1. Identify violations of BCNF.
    
2. Decompose into two relations:
    
    - `R1(COURSE_ID, INSTRUCTOR)`
        
    - `R2(STUDENT_ID, COURSE_ID)`
        

### Bullet Points:

#### Goals of Normalization:

- Avoid redundancy.
    
- Ensure data integrity.
    
- Simplify database maintenance.
    
- Minimize anomalies.
    

#### Functional Dependency:

- Relationship where one attribute determines another.
    
- Example: `ROLL_NO -> NAME`.
    

#### Superkey:

- Set of attributes uniquely identifying tuples.
    
- May include extra attributes.
    

#### Candidate Key:

- Minimal superkey with no unnecessary attributes.
    
- Example: `ROLL_NO` in `STUDENT`.
    

#### Boyce-Codd Normal Form (BCNF):

- Ensures every non-trivial functional dependency has a superkey as its determinant.
    
- Example decomposition: `COURSE` → `R1` and `R2` based on functional dependencies.
