### Topics:

- **Why should passwords be hashed?**
    
- **Why should passwords be salted?**
    
- **Why should the password hash function be iterative?**

### Reading Paper:

#### **Why should passwords be hashed?**

1. **Definition of Hashing:**
    
    - Hashing is the process of converting plain text passwords into a fixed-length string (hash) using a hash function.
        
2. **Purpose:**
    
    - **Security:** Prevents storing plain text passwords in databases.
        
    - **Irreversibility:** Hash functions are one-way, making it computationally infeasible to retrieve the original password.
        
    - **Protection Against Data Breaches:** Even if the database is compromised, hashed passwords are significantly harder to misuse.
        
3. **Common Hashing Algorithms:**
    
    - Secure: `SHA-256`, `bcrypt`, `Argon2`.
        
    - Weak (Avoid): `MD5`, `SHA-1` (vulnerable to attacks).
        

---

#### **Why should passwords be salted?**

1. **Definition of Salting:**
    
    - Adding a unique, random value (salt) to each password before hashing.
        
2. **Purpose:**
    
    - **Defeats Rainbow Table Attacks:**
        
        - Rainbow tables store precomputed hashes for common passwords.
            
        - Salting ensures each password has a unique hash, even if two users have the same password.
            
    - **Increases Hash Complexity:**
        
        - Requires attackers to compute hashes for each unique salt.
            
3. **Implementation:**
    
    - Generate a random salt for each user.
        
    - Store the salt with the hash in the database.
        
    - Example (using `bcrypt`):
        
        ```
        var salt = BCrypt.Net.BCrypt.GenerateSalt();
        var hashedPassword = BCrypt.Net.BCrypt.HashPassword(password, salt);
        ```
        

---

#### **Why should the password hash function be iterative?**

1. **Definition:**
    
    - Iterative hashing involves applying the hash function multiple times to increase computational effort.
        
2. **Purpose:**
    
    - **Mitigate Brute Force Attacks:**
        
        - Increases the time required to compute a single hash, slowing down attackers.
            
    - **Adaptability:**
        
        - Iteration count can be increased as computational power improves, maintaining security over time.
            
3. **Implementation:**
    
    - Use modern algorithms like `bcrypt`, `scrypt`, or `Argon2`, which support adjustable iterations.
        
    - Example:
        
        ```
        var hashedPassword = BCrypt.Net.BCrypt.HashPassword(password, workFactor: 12);
        ```
        
        - `workFactor` determines the number of iterations.
            

---

### Bullet Points:

- **Hashing:** Converts passwords into irreversible, fixed-length hashes to secure against data breaches.
    
- **Salting:** Adds unique, random data to each password to prevent rainbow table attacks and ensure unique hashes.
    
- **Iterative Hashing:** Slows down brute force attacks by increasing the computational cost of generating hashes.
