### Reading Paper:

#### **What is HTTP?**

The Hypertext Transfer Protocol (HTTP) is the foundation of data communication on the World Wide Web. It is a stateless, application-layer protocol that defines how messages are formatted and transmitted between clients (e.g., browsers) and servers.

---

### Protocol Stack When Using HTTP:

HTTP operates at the application layer of the OSI and TCP/IP models and relies on lower layers for communication.

1. **Application Layer (HTTP):**
    
    - Formats requests and responses.
        
    - Defines methods (e.g., `GET`, `POST`, `PUT`, `DELETE`).
        
2. **Transport Layer (TCP):**
    
    - Ensures reliable delivery of data between the client and server.
        
    - Uses the three-way handshake for connection establishment.
        
3. **Network Layer (IP):**
    
    - Handles routing of packets across networks.
        
    - Ensures the packets reach the correct destination.
        
4. **Physical and Data Link Layers:**
    
    - Enable the physical transmission of data.

### Client/Server Model:

1. **Definition:**
    
    - A communication model where the client requests resources or services, and the server provides them.
        
2. **Client:**
    
    - Sends HTTP requests to the server.
        
    - Examples: Browsers, mobile apps.
        
3. **Server:**
    
    - Processes HTTP requests and sends responses back to the client.
        
    - Hosts resources such as HTML files, images, or APIs.
        
4. **Stateless Nature:**
    
    - HTTP does not retain session information between requests.
        
    - Solutions for maintaining state: Cookies, Sessions, Tokens.

### Request/Response:

1. **HTTP Request:**
    
    - Sent by the client to request a resource from the server.
        
    - **Structure:**
        
        - **Request Line:** Contains the HTTP method, URI, and version.
            
            - Example: `GET /index.html HTTP/1.1`
                
        - **Headers:** Provide metadata (e.g., `User-Agent`, `Accept`, `Host`).
            
        - **Body:** Optional; used in methods like `POST` or `PUT` to send data.
            
2. **HTTP Response:**
    
    - Sent by the server to return the requested resource or an error message.
        
    - **Structure:**
        
        - **Status Line:** Includes HTTP version, status code, and status message.
            
            - Example: `HTTP/1.1 200 OK`
                
        - **Headers:** Provide metadata (e.g., `Content-Type`, `Server`).
            
        - **Body:** Contains the requested resource (e.g., HTML content).
            
3. **Common HTTP Status Codes:**
    
    - **2xx (Success):**
        
        - `200 OK`: Request succeeded.
            
        - `201 Created`: Resource created.
            
    - **3xx (Redirection):**
        
        - `301 Moved Permanently`: Resource moved to a new URL.
            
        - `302 Found`: Temporary redirect.
            
    - **4xx (Client Error):**
        
        - `400 Bad Request`: Invalid request syntax.
            
        - `404 Not Found`: Resource not found.
            
    - **5xx (Server Error):**
        
        - `500 Internal Server Error`: Generic server error.
            
        - `503 Service Unavailable`: Server overloaded or under maintenance.
            

---

### Bullet Points:

- **HTTP:** Stateless, application-layer protocol used for web communication.
    
- **Protocol Stack:** HTTP operates over TCP/IP, ensuring reliable data transmission.
    
- **Client/Server Model:** Clients send requests; servers respond with resources or errors.
    
- **Request/Response Cycle:**
    
    - Request: `Method`, `URI`, headers, and optional body.
        
    - Response: Status code, headers, and optional body.
        
- **Common Status Codes:** `200 OK`, `404 Not Found`, `500 Internal Server Error`.
