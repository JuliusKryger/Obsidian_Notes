### Reading Paper:

#### **What is REST?**

Representational State Transfer (REST) is an architectural style for building web services. It defines a set of constraints that ensure scalability, simplicity, and performance in communication between clients and servers.

#### **Key Characteristics of REST:**

1. **Stateless:**
    
    - Each request from the client to the server must contain all the necessary information to process the request. The server does not store client state.
        
2. **Client-Server Architecture:**
    
    - Separation of concerns between the client (user interface) and server (data storage and processing).
        
3. **Resource-Based:**
    
    - Resources (e.g., users, posts) are identified by URIs (Uniform Resource Identifiers).
        
4. **HTTP Methods:**
    
    - **GET:** Retrieve data.
        
    - **POST:** Create new resources.
        
    - **PUT:** Update existing resources.
        
    - **DELETE:** Remove resources.
        
5. **Hypermedia as the Engine of Application State (HATEOAS):**
    
    - Clients navigate the application by following links provided dynamically by the server.
        
6. **Caching:**
    
    - Responses must be labeled as cacheable or non-cacheable to improve performance.

### Interface Design & Hypermedia:

1. **Interface Design:**
    
    - Focus on simplicity and clarity in exposing API endpoints.
        
    - Use consistent naming conventions and versioning for APIs.
        
    - **Example of a RESTful Endpoint:**
        
        - `GET /api/v1/users` → Retrieves all users.
            
        - `POST /api/v1/users` → Creates a new user.
            
2. **Hypermedia:**
    
    - Provides links to related resources within responses, allowing clients to navigate without hardcoding URIs.
        
    - **Example Response with Hypermedia:**
        
        ```
        {
          "user": {
            "id": 1,
            "name": "John Doe",
            "links": [
              { "rel": "self", "href": "/api/v1/users/1" },
              { "rel": "posts", "href": "/api/v1/users/1/posts" }
            ]
          }
        }
        ```

### Authentication:

1. **Basic Authentication:**
    
    - Encodes username and password in the `Authorization` header.
        
    - **Example Header:**
        
        ```
        Authorization: Basic base64(username:password)
        ```
        
    - **Drawback:** Not secure unless used over HTTPS.
        
2. **Token-Based Authentication:**
    
    - Issues a token (e.g., JWT) upon login, which the client includes in subsequent requests.
        
    - **Example Header:**
        
        ```
        Authorization: Bearer <token>
        ```
        
3. **OAuth 2.0:**
    
    - A widely used framework for delegated access.
        
    - **Flow:**
        
        - User authorizes the application.
            
        - Application receives an access token to interact with resources.
            
4. **API Keys:**
    
    - A unique key assigned to clients to access the API.
        
    - Often included in the query string or headers.
        

---

### Bullet Points:

- **REST:** Architectural style for scalable web services.
    
- **HTTP Methods:** `GET`, `POST`, `PUT`, `DELETE` for CRUD operations.
    
- **Hypermedia:** Enables dynamic navigation through links in responses.
    
- **Authentication Methods:**
    
    - Basic Authentication: Simple but requires HTTPS.
        
    - Token-Based: Uses tokens for secure access.
        
    - OAuth 2.0: Delegated access control.
        
    - API Keys: Unique keys for client identification.
